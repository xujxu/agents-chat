Scope agreed 2026-09-24
---------------------
One active local model per deployment, chosen by the administrator at install.
The browser continues to use authenticated /api/voice, independent of engine.
No per-chat model switching, public model server, silent fallback, automatic
resource expansion or changes to current PROD/cpg/service defaults.

Most target deployments are CPU-only shared servers, e.g.8cores/16GB or
16cores/32GB. Total host capacity is NOT the voice budget. Installation must
show compatible CPU architecture/instructions, allocated threads/CPU quota,
measured process/container memory, recommended reserved capacity, model size,
license, quality/latency status and evidence source for each exact combination.
Do not report GPU VRAM, model download size or parameter-derived estimates as
measured CPU RAM requirements. Unknown measurements block recommended status.

The deployable identity is model + weight revision/quantization + engine build
+ resource profile. Resource compatibility and quality acceptance are separate.
Keep the current1thread/384MiB monitoredRSS/1GiBAS profile unchanged. Any larger
profile requires an explicit administrator choice and must not consume all host
resources. Admission, cancellation and timeout must apply to the entire backend.
Large or persistent workers need independent process-tree memory enforcement,
idle-memory accounting and crash/cancellation recovery before installation.

License admission
-----------------
Verify weights, runtime and redistributed dependencies independently. Prefer
MIT/Apache-2.0/BSD-style permissions permitting use, commercial use and
redistribution; retain notices. No custom/unclear license is automatically
admitted. No claim of zero legal risk.
Whisper weights/code are MIT. Existing static binaries additionally include
GCC runtime libraries under GPL with the standard GCC Runtime Library Exception;
never label the complete distribution "MIT only".

The exact official Fun-ASR-Nano-2512 and Nano-GGUF model cards declare Apache-2.0;
these are candidates, not a blanket approval of every FunASR model/package.
Original SenseVoiceSmall points to a custom license, while official
SenseVoiceSmall-GGUF declares Apache-2.0. Resolve that exact artifact's applicable
permission before distribution; don't infer relicensing from a format change.
Qwen3-ASR0.6B/1.7B official cards and official inference code declare Apache-2.0;
converted weights, tokenizer and full runtime dependency tree require review.
Historical internal experiments do not grant redistributable-install status.

--------------------------------------

   propagation, failure-inclusive scoring, and incomplete/mismatched evidence.
   Run tests in GitHub Actions; no local test/build/model workloads.

   cpu2-ram4 =2 model threads,2CPU quota,4GiB container memory;
   cpu4-ram8 =4 model threads,4CPU quota,8GiB container memory.

   6 each zh/en/mixed at<=5s,3 each zh/mixed at15-30s; hash ordering with a fixed
   seed. No concatenation or transcript-based sample choice. This is a resource
   screen with indicative scores, not a new untouched holdout or finalP95 claim.
   Every timeout, OOM, empty and invalid output stays in delivered scoring.
5. Measure cold request latency including process/model loading, peak RSS and

Installation and upgrade flow design, 2026-09-24
-----------------------------------------------
The user explicitly selected: prompt on EVERY interactive upgrade, with keep
current configuration as the default. Voice setup is not first-install-only.
This design extends the approved catalogue, native execution and resource policy;
it does not change model qualification gates or introduce a compulsory service.

Entry points and interaction:
- A reusable configuration command serves fresh installation, upgrades and
  later reconfiguration. Linux deploy.sh invokes it after obtaining the new
  application version and before activating/restarting the service.
- Interactive first install with no configuration defaults to voice disabled.
  Interactive upgrade displays effective current state and defaults to KEEP,
  including preservation of an old Whisper/legacy-low-memory configuration.
- The menu permits keep, configure Sense GGUF q8, configure Whisper compatibility,
  or disable. Model entries show qualification status, weight/runtime license,
  download size, tested CPU/thread/memory observations and platform requirements.
  Sense is not advertised as release-approved before remaining package gates.
- Noninteractive installs/upgrades never read stdin or wait for a choice. With no
  explicit selection they preserve current configuration (disabled if absent),
  print current state and the exact reconfiguration command, and continue.
  Explicit command-line selections use the same validation/install transaction.
- Closing input or cancelling the menu preserves the current configuration.
  An explicitly requested setup that fails exits nonzero; it is not reported
  as successful configuration or silently replaced with another model.
- Merely starting/restarting the app never opens an installation prompt.
- Choosing not to install voice on a fresh installation, or explicitly disabling
  voice during upgrade/reconfiguration, persists disabled capability. After the
  configuration takes effect and the page reloads, the composer must omit the
  voice button entirely, not show a greyed-out button or an installation warning.
  No model download, inference process or microphone permission request occurs
  for disabled voice. Keeping an already-enabled configuration is distinct from
  explicitly disabling it; the menu must make that distinction clear.

Upgrade and configuration preservation:
- Read only voice-related keys for display. Never print authentication values
  or rewrite unrelated environment settings.
- Keep means no voice configuration migration, model download, policy change or
  automatic enablement. An explicit switch to a new model uses standard policy.
- Report higher-priority service environment overrides, including
  /etc/agents-chat.env, rather than claiming a project setting will take effect
  when it is overridden. Do not silently modify machine-level overrides.
- Preserve prior model/configuration until the new selection is fully prepared
  and verified. Stage downloads and configuration separately; commit configuration
  atomically only after all required checks succeed. Retain a recoverable prior
  configuration for a failed activation. Do not delete old model assets on switch.
- The first upgrade from an OLD deploy script must also reach the new setup
  logic: do not rely solely on code parsed by the shell before git pull.
  An already-running historical script cannot be retroactively changed. The
  documented bootstrap is git pull --ff-only followed by the NEW deploy.sh
  --no-pull. The new upgrade.sh entry point and deploy.sh re-exec after pull
  handle subsequent upgrades. This first-migration command is required, not an
  automatic capability of old releases.

Supported distribution surfaces:
- Initial native packages are Linux x86_64 only. Windows/macOS install/upgrade
  documentation must clearly report unsupported local speech packages, not
  offer a Linux binary as a working native option.
- Standalone release bundles include the configuration command and instructions,
  rather than assuming users have the source checkout or development dependencies.
  Replacing app files must preserve external configuration/model data.
- Pin portable runtime build identity and each downloaded model/runtime checksum.
  Retain weight declarations, source revisions, the native patch, engine licenses
  and relevant transitive/system-library notices alongside installed assets.
- Current Actions-built smoke binaries are not release packages. Build/qualify
  portable bundles in Actions before enabling their installer catalogue entries.
  Tests use controlled download fixtures and Actions artifacts. Public release
  publication is a separate explicit step, not an implicit production deployment.

Compatibility and resource guidance:
- Reject incompatible architecture/instruction set/runtime dependencies, corrupt
  downloads, invalid paths and insufficient disk for staging/installation.
- Present actual available CPU/memory and existing deployment constraints, with
  measured model use and uncertainty. Low-resource warnings do not manufacture
  a minimum4GiB requirement from the experimental allocation.
- No mandatory new cgroup, Docker or systemd voice unit. Thread configuration is
  not a CPU quota; standard mode has no added CPU/RAM cap. Explain that operators
  may set deployment limits, and insufficient memory can still cause failure.

Actions-only acceptance:
- Test fresh interactive selection, every-upgrade prompting, default keep,
  explicit disable/model switch, cancelled input and noninteractive preservation.
- Verify fresh-install opt-out and enabled-to-disabled upgrade produce
  /api/voice enabled=false and no microphone button or voice-error banner after
  reload. Preserve the current frontend's disabled-capability rendering.
- Test old Whisper compatibility and old versions without ANY voice keys.
- Test old deploy-script upgrade reaching the new configurator, environment
  override detection, portable bundle inclusion and unsupported-platform errors.
  Distinguish the documented first-migration bootstrap from the tested new-script
  re-exec path; never claim an unmodified old running shell gains new behavior.
- Test corrupt/truncated downloads, interruption, concurrent setup protection,
  staging cleanup, unchanged previous settings on failure and activation recovery.
- Run real pinned native artifacts through the installed configuration and
  authenticated API, plus browser capture/cancellation and frozen quality/latency
  gates. No production enablement follows merely from passing fixture tests.
