Install-selected voice providers: approved direction and evidence plan
===================================================================

Scope agreed 2026-09-24
---------------------
One active local model per deployment, chosen by the administrator at install.
The browser continues to use authenticated /api/voice, independent of engine.
No per-chat model switching, public model server, silent fallback, automatic
resource expansion or changes to current PROD/cpg/service defaults.

Most target deployments are CPU-only shared servers, e.g.8cores/16GB or
16cores/32GB. Total host capacity is NOT the voice budget. Installation must
show compatible CPU architecture/instructions, allocated threads/CPU quota,
measured process/container memory, recommended reserved capacity, model size,
license, quality/latency status and evidence source for each exact combination.
Do not report GPU VRAM, model download size or parameter-derived estimates as
measured CPU RAM requirements. Unknown measurements block recommended status.

The deployable identity is model + weight revision/quantization + engine build
+ resource profile. Resource compatibility and quality acceptance are separate.
Keep the current1thread/384MiB monitoredRSS/1GiBAS profile unchanged. Any larger
profile requires an explicit administrator choice and must not consume all host
resources. Admission, cancellation and timeout must apply to the entire backend.
Large or persistent workers need independent process-tree memory enforcement,
idle-memory accounting and crash/cancellation recovery before installation.

License admission
-----------------
Verify weights, runtime and redistributed dependencies independently. Prefer
MIT/Apache-2.0/BSD-style permissions permitting use, commercial use and
redistribution; retain notices. No custom/unclear license is automatically
admitted. No claim of zero legal risk.
Whisper weights/code are MIT. Existing static binaries additionally include
GCC runtime libraries under GPL with the standard GCC Runtime Library Exception;
never label the complete distribution "MIT only".

The exact official Fun-ASR-Nano-2512 and Nano-GGUF model cards declare Apache-2.0;
these are candidates, not a blanket approval of every FunASR model/package.
Original SenseVoiceSmall points to a custom license, while official
SenseVoiceSmall-GGUF declares Apache-2.0. Resolve that exact artifact's applicable
permission before distribution; don't infer relicensing from a format change.
Qwen3-ASR0.6B/1.7B official cards and official inference code declare Apache-2.0;
converted weights, tokenizer and full runtime dependency tree require review.
Historical internal experiments do not grant redistributable-install status.

Evidence-first implementation sequence
--------------------------------------
1. Add failing tests for fixed profiling sample coverage, voice budget/thread
   propagation, failure-inclusive scoring, and incomplete/mismatched evidence.
   Run tests in GitHub Actions; no local test/build/model workloads.
2. Profile larger CPU candidates with explicit isolated budgets:
   cpu2-ram4 =2 model threads,2CPU quota,4GiB container memory;
   cpu4-ram8 =4 model threads,4CPU quota,8GiB container memory.
   These are trial allocations, not universal minimums or host-size labels.
3. Reuse pinned native runtimes and artifact checksums. Initial cold-process
   screen: Whisper small-q5_1, large-v3-turbo-q5_0, FunASR-Nano safe U8U8 ONNX,
   Qwen3-ASR0.6B INT8 ONNX. Compare sequentially on the same runner within a
   profile; record CPU identity and quota instead of claiming to simulate an
   entire8/16-core deployment. Do not silently substitute native/FP32/GGUF paths.
4. Use24 predetermined probes from the existing frozen100-sample chain corpus:
   6 each zh/en/mixed at<=5s,3 each zh/mixed at15-30s; hash ordering with a fixed
   seed. No concatenation or transcript-based sample choice. This is a resource
   screen with indicative scores, not a new untouched holdout or finalP95 claim.
   Every timeout, OOM, empty and invalid output stays in delivered scoring.
5. Measure cold request latency including process/model loading, peak RSS and
   cgroup memory/OOM events. Missing measurements stay unknown. Native model
   workers and whole-container memory are separate quantities. Filesystem cache
   may be warm. This stage does not measure a resident model's idle/warm latency.
6. Inspect runtime/model notices in downloaded packages before installer
   admission. Deferred/rejected variants remain visible in experiment reports,
   not selectable as approved installs.
7. After resource/permission review, define the first installable catalogue and
   implement focused model/config/engine boundaries, atomic verified downloads,
   explicit resource selection and a disabled option. Unknown models/configs
   fail explicitly. Preserve legacy Whisper configuration with truthful API
   metadata, and document precedence/migration.
8. Exercise installer corruption/rollback/disabled/missing-resource cases and
   actual API delivery/model metadata/cancellation/memory recovery in Actions.
   Run build/typecheck and relevant existing E2E; do not deploy this work.

The installer is not implemented yet. Do not publish unmeasured resource minima
or mark the experimental candidates as approved installation choices.

Implementation design revision approved2026-09-24
------------------------------------------------
This section supersedes any earlier implication that every new installation
must use a fixed2CPU/4GiB allocation or separate systemd/Docker voice service.
The local cpg workaround is only for this machine's Copilot CLI, not a product
dependency, installer prerequisite or policy for other deployments.

Default to native per-request model processes with configurable computation
threads, one active job,120second deadline, cancellation and bounded output.
Do not impose experiment CPU/RAM hard limits on explicit new-model configuration.
Respect externally configured OS/container limits; hard quotas are an optional
operator deployment policy, not implied by a thread setting or advertised as an
application guarantee. Preserve old Whisper environment behavior through an
explicitly named legacy-low-memory policy; do not silently change old deployments.

First implementation slice:
1. tests/voice-providers.test.ts specifies model whitelist, disabled/invalid
   configuration, standard versus legacy policy, command arguments and output.
   voice-providers.yml runs it in Actions before implementation (expected red).
2. lib/voice/configuration.ts owns typed model/configuration/capability metadata.
   Explicit VOICE_MODEL selects sensevoice-small-q8 or whisper-base-q5_1.
   VOICE_BINARY_PATH and VOICE_MODEL_PATH are absolute native artifact paths.
   VOICE_THREADS accepts1/2/4 to match the pinned Sense CLI; defaults2 for Sense,
   1 for Whisper. VOICE_RESOURCE_POLICY defaults standard for explicit models.
   Old VOICE_WHISPER_PATH without VOICE_MODEL preserves legacy-low-memory.
   That policy remains one-thread Whisper only, with the unchanged old guards.
3. lib/voice/providers.ts owns model-specific arguments and strict bounded UTF-8
   output. transcriber.ts owns subprocess/temp-file lifecycle and kills process
   groups on cancellation/failure. Existing {binary,model} benchmark callers
   retain legacy behavior. No transcript, raw output or audio is logged.
4. app/api/voice/route.ts reports the real provider/model/threads/policy, null
   model when disabled, and applies legacy admission only to legacy policy.
   Authentication, account/origin checks, WAV limits and global admission stay.
5. Fixture subprocess/API/browser tests plus real pinned Sense smoke run only
   in Actions. Include nonzero exit, empty/oversized/invalid output, cancellation,
   missing files and cleanup; build/typecheck and old Whisper API regressions.

This slice does not implement installation selection or publish an approved
package. Next slices add verified atomic downloads/rollback, dependency notices,
resource guidance/compatibility checks and real full-corpus API/browser gates.
No runtime artifacts or services are installed on this development machine.
