Frozen budget-constrained model decision experiment
==================================================

User-approved scope 2026-09-24: Whisper base-q5_1 versus SenseVoice INT8 whole
and bounded segmented SenseVoice. FunASR prior results remain context, not a
fresh candidate under384MiB. No deployment, host workload or resource changes.

Run Budget-constrained voice model selection in GitHub Actions only.
Use the fixed memory guard, 1 thread, 384MiB RSS, 1GiB address space, 120s timeout.
Every utterance goes through actual transcribeVoice and PCM validation, not a
parallel imitation of the guard. Failed attempts remain in scoring.

Development: pinned ASCEND validation partition,8 longest valid original
utterances from each zh/en/mixed category. No artificial long concatenation.
Predefined segment maxima2/3/5seconds. A simple energy boundary is selected in
the final quarter (up to1s) of the bounded segment using10ms energy windows.
Frames are assigned exactly once: no dropped silence, overlap or transcript
deduplication. One recognizer load per request, new stream for each segment.
Join nonempty segment text with spaces; expose accuracy loss through scoring.
Select only a configuration with no failed/empty development output, by lowest
micro error thenP95. If none qualifies, do not promote a failed configuration.
Record frozen selection before downloading/evaluating the test corpus.

Test: the existing fixed hash-ranked60 ASCEND short probes plus40 original
AISHELL-4 continuous15-30s windows. No changing the sample set based on output.
Shared input hashes; all candidates run sequentially on one Actions runner.
Use prior whole-Sense references on exactly those same samples as the quality
comparator. Its scores were measured unconstrained, not a deployment baseline.
Retain per-category/duration rates; do not compare only successful outputs.

Predetermined gates:
-100% successful nonempty delivery, no limit/timeout failures.
-Each language/duration error rate <= whole-Sense on same samples +2points.
-Input <=5s: cold request P95 <=3s; input15-30s: P95 <=5s.
 Aggregate latency by duration band; language-specific latency is diagnostic.
 Intermediate5-15s latency is reported, not given an invented threshold.
-Among eligible candidates choose lower mixed error; within1point choose lower
 overallP95. Corpus rates are micro CER/WER/MER, not sentence accuracies.

Timing here includes validation/temporary audio/model cold start/cleanup, but
not HTTP or browser overhead. Passing this stage is preliminary: a candidate
must repeat the gates in the real browser/API path before product acceptance.
No eligible candidate is a valid outcome. Do not select a winner by relaxing
budgets or gates after seeing results.

All corpora here have already been explored. Frozen development/test separation
for this experiment does not prove pretraining independence or new holdout
generalization. Long mixed coverage is only11 annotation-mixed meeting windows.
CI CPU is not the deployed host. Silence/VAD and real microphone noise remain
separate coverage limitations. The original native runtimes' licenses and both
CC-BY-SA corpus attributions accompany artifacts.

The bounded segmented adapter is CI-only and changes no product behavior.
Stages are independently persisted to survive CLI session interruption:
voice-choice-development and voice-choice-test-decision.

Results and decision: 2026-09-24
===============================

Decision: NONE of the approved candidates meets the fixed gates.
Do not ship Whisper just because it fits memory; do not ship Sense just because
its successful requests are fast. No browser acceptance rerun is needed to
reject candidates already failing actual-transcriber screening.

Inference commit 9be8888, Actions 35944684486.
Development artifact 10786098480; test artifact 10787280400.
Reviewed report commit 4dfa740, Actions 35946323331, artifact 10786533959.
The review uses the exact same inference outputs, not a new model run. It
corrects latency gating to aggregate duration bands (not individual languages),
enforces complete candidate evidence, and labels rejection timing explicitly.
This reporting correction does not change the no-winner decision.

Development, 24 official validation examples:
  segment-2: 19 delivered, 5 voice_memory_limit.
  segment-3: 19 delivered, 5 voice_memory_limit.
  segment-5: 19 delivered, 5 voice_memory_limit.
No configuration meets the preregistered all-delivered development gate.
frozen.json therefore contains variant:null. No segmented test candidate was
substituted after seeing test results. These results establish failure of these
implementations, not impossibility of every segmentation technique.

Whisper exceeds both aggregate latency limits (3s/5s) before HTTP/browser
overhead. Its long Mandarin CER is34.36% versus10.76% for the identical-input
unconstrained Sense baseline. Long mixed MER is40.58% versus14.70%; short
mixed MER31.29% versus19.05%. It fails the +2point quality gate as well.
All quality scores compare identical samples, not full-corpus versus subsets.

Sense long failure-inclusive error is100% because no transcript was delivered;
that is not its unconstrained linguistic recognition error. Its2.42s long
attempt P95 measures rejection, NOT fast transcription.

Memory: complete CI service logs contain272 numeric sampledPeakRssKiB records,
one for each72 development +200 test attempts in sequential workflow order.
The dev maxima were443.95/428.54/443.89MiB for2/3/5s respectively.
Whisper native final HWM remains null in per-row artifacts;152.58MiB above is
the existing service monitor's sampled HWM, not an invented native measurement.
The100ms RSS guard can observe a transient overshoot before killing the child;
384MiB remains the rejection budget, not a hard RSS cgroup. All69 failures
across development and test were voice_memory_limit; zero voice_memory_unknown.
This is evidence the prior exit-race fix remains effective in this experiment,
not evidence that the separate CLI OOM problem is resolved.

No production configuration, deployment, cpg limit or sampler changed.
The chosen candidate set is exhausted under the approved gates. Further work
requires a separately defined implementation/model hypothesis, not adjusting
these gates or repeatedly tuning against these test outputs.
