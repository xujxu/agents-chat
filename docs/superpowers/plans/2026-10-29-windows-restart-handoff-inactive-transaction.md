# Windows Restart Handoff-Aware Inactive Transaction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After its handoff-aware inactive admission (gate 62), the exact live restart owner begins the existing inactive task transaction (`beginWindowsInactiveTaskTransaction`) through the same handoff-aware scope. It advances its written preflight to `stopped`, then reaches the `copying` snapshot stage bound to the proved task observation. Copied scopes, foreign admission digests and duplicate transaction consumers stay refused.

**Architecture:** Continues `docs/superpowers/specs/2026-10-26-windows-stopped-history-handoff-design.md` ("Subsequent states use existing transaction checks"). The transaction reads state through `assertWindowsInactiveTaskAdmissionBinding`, which uses only the native `check` method. The handoff-aware controller already grants that method. No new primitive is added unless Actions shows the existing checks refuse the handoff scope.

**Tech Stack:** `tests/deployment-windows-restart-preparation.mjs` (`refuseAdmission` block, `commitment` shard), `scripts/deployment/windows-inactive-task-transaction.mjs`, `.github/workflows/deployment-lifecycle.yml` (69 receipts). All validation runs only in GitHub Actions.
